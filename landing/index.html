三個讓申報卡住的地方

人工對帳要好幾天，退件只給一個代碼。

財務與精算部門的申報資料來自銷售、理賠、投資等上游系統，格式複雜、檔案龐大。檢核助手針對下面三個痛點設計。

跨系統時間差
「理賠系統的 12 月給付，跟申報明細差了 200 萬。」

逐月比對上游控制總數，自動找出落在結帳邊界、金額恰好等於差額的那一筆，判定為時間差、口徑定義差或需要追查。

計算矛盾與代碼錯置
「資產負債表不平，期初期末也兜不攏。」

檢查科目結轉、上下層加總、資產 = 負債 + 權益，並把同一差額串成根因；停用科目提示替代代號，打錯的代號推薦正確值。

退件黑盒子
「退件只寫 Error 504：欄位驗證失敗。」

貼上退件訊息，辨識手冊檢核編號、行號與欄位名稱；籠統代碼依前綴或關鍵字推定類別，列出每一筆的位置與修正值。

依填報手冊逐欄、逐筆檢核

個人壽險承保檔（425 字元、61 欄）與給付檔（225 字元、31 欄），檢核編號沿用手冊的「(新)檢核編號」，每個錯誤都能對回條文。

  • 格式：長度、全形字、數字欄前補 0、文數字靠左
  • 代碼：加保別、退保別、商品類別編號編碼原則
  • 邏輯：日期先後、異動序號、停效後須復效、承保與給付跨檔
  • 可推得正確值的錯誤，一鍵套用修正

與上游系統控制總數對帳

申報明細依新契約、理賠、保單管理系統各自的口徑彙總後比對。差異會被分成三類，只有「待查」需要動手修正。

  • 時間差：指出造成差額的那幾筆交易
  • 定義差：例如外幣保單以原幣加總
  • 待查：連結可能相關的明細錯誤

資產負債表勾稽與根因串連

同一個差額出現在多個檢核時，指出唯一的源頭。修一處，連帶的錯誤一起消失。

  • 期初 + 增加 − 減少 = 期末
  • 上層科目 = 下層合計；資產 = 負債 + 權益
  • 停用科目與打錯的代號，推薦正確值
  • 應付保險給付與給付明細勾稽

使用流程

四個步驟，申報前完成。

匯入資料

拖入承保檔、給付檔；選填上年度申報檔、上游控制總數與資產負債表。也接受 CSV。

自動檢核

逐欄、逐筆、跨檔驗證，同時完成控制總數對帳、結轉與財報勾稽。

定位與修正

欄位尺規標出錯誤的字元位置；能推得正確值的錯誤一鍵套用，下載修正檔。

產出報告

HTML 報告、問題清單 CSV、不符資料檔，加上 Claude 撰寫的根因摘要。

規則引擎 × AI

判定交給規則，解讀交給 AI。

RULE ENGINE

可重現、可稽核

每一個錯誤都由規則引擎判定，對得回填報手冊條文或會計科目表。同樣的資料，永遠得到同樣的結果。

CLAUDE

歸納根因、排定優先順序

把幾十項錯誤歸成「轉檔未補前置 0」「各系統結帳時點不同」這類系統性原因，區分要改申報檔與只需在底稿說明的差異，並解讀退件訊息。送出的只有檢核摘要，不含個資。
