# 法規更新與主管核可：測試步驟

搭配試用資料 `samples/excel/試用資料_含錯誤.xlsx` 使用（放入後「待修正問題」是 82 項、全部問題 86 個）。所有檔案都是虛構的測試內容。

| 檔案 | 內容 | 匯入後應該看到 |
|---|---|---|
| `1_新增檢查_待核可.json` | 臺幣保額超過 2,000 萬列為「建議確認」 | 標示「待主管核可・不會套用」，結果不變；按「試跑」→ 新檢查會找到 2 個問題 |
| `2_停用檢查_待核可.json` | 停用 30212_L1305、30205_P0502 | 待主管核可，結果不變；試跑 → 停用會隱藏 4 個問題 |
| `3_新增欄位_待核可.json` | 保留欄位第 1 碼改為「數位投保註記」(虛構情境) | 待主管核可；試跑 → 新檢查會找到 6 個問題 |
| `4_有錯的更新包.json` | 用了不存在的欄位、停用不存在的編號 | 列出格式不對的項目，整包都不會套用 |
| `5_核可申請_停用檢查.json` | 「2_停用檢查」的核可申請檔 | 給主管測試核可用（見下面第 2 步） |
| `6_已核可_新增檢查.json` | 「1_新增檢查」已由測試主管核可（正式主管金鑰簽章） | **直接套用**：標示「主管已核可・測試主管」，多 2 個「建議確認」 |
| `7_已核可_被竄改.json` | 同上，但有人把門檻從 2,000 萬偷改成 2 億 | **不套用**：「主管簽章不正確：更新包內容、核可人或核可時間被改過」 |

## 1. 一般同仁：匯入、試跑、申請

1. 打開工具，放入 `試用資料_含錯誤.xlsx`。
2. 頁尾「進階功能」→「法規更新」→「匯入規則更新包」，選 `2_停用檢查_待核可.json`。
3. 確認：更新包標示「待主管核可・不會套用」，「檢查結果」的問題數沒有變。
4. 按「試跑」：顯示「停用會隱藏 4 個問題」，問題數仍然沒有變。
5. 按「申請主管核可」、填申請人姓名 → 下載「核可申請_test-disable_日期.json」，寄給主管。

## 2. 主管：核可

1. 打開工具的「法規更新」頁，展開「主管核可」。
2. 「核可申請檔」放入同仁寄來的申請檔（或測試用的 `5_核可申請_停用檢查.json`），確認下方列出的內容。
3. 「核可私鑰」放入主管的私鑰檔（`dq-pack-signing-key.pem`），填核可人姓名。
4. 按「核可並產生已核可檔」→ 下載「已核可_test-disable.json」，回傳給同仁。
   - 用別把私鑰會顯示「不是這個版本核准的主管金鑰」。

## 3. 一般同仁：套用

1. 「匯入規則更新包」放入「已核可_test-disable.json」。
2. 確認：標示「主管已核可・核可人・日期」，問題少了 4 個，畫面與報告註明「結果不完整」（有檢查被停用）。
3. 再匯入 `7_已核可_被竄改.json`：顯示簽章不正確、不套用。
4. 在「新增一條檢查」加一條檢查：會放進「本機自訂更新」，待主管核可、不套用。

重新產生這些檔案：`node tools/make-update-samples.js <主管私鑰.pem>`（不給私鑰時只產生不需要簽章的檔案）。
