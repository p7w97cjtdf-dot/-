# 申報資料檢核助手 · Finance & Actuarial Validation Assistant

THEME 6 | Finance, Actuarial & Data Management — **6-2 資料品質與檢核助手**

## 情境：法規申報與精算/財務數據大表匯入

財務與精算部門定期要向金管會、保發中心申報大量財務報表、準備金與精算資料。資料來自銷售、理賠、投資等多個上游系統，格式複雜、檔案龐大，人工對帳往往要好幾天；一旦被退件，通常只拿到籠統的錯誤代碼，要在數萬筆資料裡重新翻找。

本工具在匯入/申報**之前**，依既定檢核規則全自動驗證資料，並把每個問題定位到「哪個檔、第幾行、哪個欄位、應該改成什麼」。

| 痛點 | 本工具的做法 |
|---|---|
| **1. 跨系統整併的時間差斷層**：各系統結帳時點、口徑不同，金額兜不攏，只能人工比對 | **上游控制總數對帳**：申報明細依各系統口徑彙總，與新契約、理賠、保單管理系統的控制總數逐期比對。有差異時自動歸因：**時間差**（找出落在結帳邊界、金額恰好等於差額的那幾筆，例如 12/30 給付被理賠系統算到次年 1 月）、**定義差**（例如外幣保單以原幣加總）、或**待查**（找不到可解釋的原因，並連結相關的明細錯誤）。時間差與定義差只需在對帳底稿說明，不必改申報檔 |
| **2. 跨欄位計算矛盾、代碼錯置**：加總不平、期初期末結轉兜不攏、使用錯誤或已失效的代號 | **財報勾稽**：期初 + 增加 − 減少 = 期末、上層 = 下層合計、資產 = 負債 + 權益，並做**根因串連**——同一個差額出現在多個檢核時，指出唯一的源頭（例：責任準備金一個數字對調 → 保險負債、負債總計、資產負債表不平共 4 個錯誤，修一處全解）。**停用科目**（如 IFRS 9 後停用的「備供出售金融資產」）提示替代科目；**代號錯置**（1401 打成 1410）比對數字對調/誤植，推薦正確代號。<br>**期初/期末結轉**：上年度申報檔期末 vs 本年度期初逐保單勾稽（漏報、保額不一致），並產出保額變動表，找出「保額變了卻沒有對應異動」的保單。<br>**明細檢核**：依填報手冊 256 條規則檢查格式、代碼（含商品類別編號編碼原則）、單筆與多筆邏輯、承保與給付跨檔 |
| **3. 退件的黑盒子**：只給「Error 504：欄位驗證失敗」，不知道錯在哪一列 | **退件解碼**：貼上退件訊息，辨識手冊檢核編號（新舊編號皆可，如 `30212_L1305`、`L0612`）、行號、欄位名稱；籠統代碼則依代碼前綴或關鍵字推定錯誤類別。依目前資料重新檢核後，列出所有具體位置與修正值，並可請 AI 解讀退件訊息、擬定修正順序 |

另外：
- **修正建議與自動修正**：每項問題都有建議；可推得正確值的（年滿期迄日、異動序號、補前置 0…）可單筆或一鍵套用，下載修正後檔案
- **檢核報告**：獨立 HTML 報告（含對帳與財報章節）、問題清單 CSV、保發中心風格的不符資料檔
- **AI 分析（Claude）**：把明細錯誤、對帳差異、財報問題一起歸納成系統性根因，區分「要改申報檔」與「只需在底稿說明」，排出修正優先順序並評估退件風險

### 規則匯入：上傳規則文件，由 AI 轉成可執行規則

主辦單位或公司內部的檢核規則文件（PDF、Word、文字檔）可以直接上傳。流程：

1. **讀取文件**：在瀏覽器內擷取文字（PDF 用 pdf.js、Word 用 mammoth），檔案不會上傳。長 PDF 會自動建議檢核條文最集中的頁數（例如《檢核規則_2025》建議第 46–63 頁）。
2. **Claude 轉換**：分段送給 Claude，附上兩個申報檔的欄位字典與規則格式說明，轉成 JSON 規則。規則是宣告式條件（欄位、比較、日期與金額函式、同保單上一筆），**不執行任何 AI 產生的程式碼**。
3. **自動審核**：每條規則先做格式驗證（欄位存在、運算合法），再在「正確範例資料」上試跑。在正確資料上就觸發的規則標為「疑似轉錯」，與內建規則同編號的標為「與內建相同」，預設都不勾選。
4. **人工確認後套用**：卡片上並列原文、規則的中文說明（「當…必須…」）與目前資料的不通過筆數。勾選套用後與內建規則一起執行，結果出現在明細檢核，類別為「匯入規則」。規則可下載成 JSON 保存、再匯入。

內附兩份範例文件：「公司內部核保規則」（內建檢核沒有的規則，例如 3,000 萬元以上新契約須體檢、75 歲以上不得承保終身壽險），以及「填報手冊檢核條文節錄」（可與內建規則對照，驗證轉換正確性）。沒有 AI 可用時，可按「載入預先轉換結果」展示完整流程。

### 規則引擎與 AI 的分工

判定對錯一律由規則引擎執行：結果可重現、可稽核，每一項都能對回手冊條文或科目表。AI 負責**解讀**：歸納根因、排定優先順序、把籠統的退件訊息翻成具體行動。送給 AI 的只有檢核摘要與問題清單，不含證件號碼等個資。AI 功能使用 `claude-opus-5-5`，需要 Anthropic API key（到 https://console.anthropic.com/settings/keys 建立）。沒有 key 時其他功能都能使用。設定方式二選一：

- 在頁面「AI 分析」欄位貼上 key，只會存在自己的瀏覽器。
- 本機展示用：把 `config.example.js` 複製成 `config.local.js` 並填入 key，頁面開啟時自動帶入。`config.local.js` 已列入 `.gitignore`，**不要把 key commit 到 GitHub 或放進公開網頁**，任何能開啟頁面的人都看得到瀏覽器端的 key。

## 快速開始

直接用瀏覽器開啟 `index.html`，頁面已載入一組含錯誤與差異的模擬資料（5 個檔案）。

```bash
# 命令列 (Node 18+)：有錯誤時 exit code = 1，可接在轉檔/匯入排程之後
cd samples/dirty
node ../../tools/validate.js LFL01_2025.txt LFD01_2025.txt \
  --prior LFL01_2024.txt --control 控制總數_2025.csv --statement 資產負債表_2025.csv --html 檢核報告.html

npm test          # 測試
npm run samples   # 重新產生模擬資料
```

### 輸入檔案

| 檔案 | 格式 |
|---|---|
| 承保資料檔 `LFLxx_yyyy.txt` | 固定長度 425 字元、61 欄（也接受 CSV） |
| 給付資料檔 `LFDxx_yyyy.txt` | 固定長度 225 字元、31 欄（也接受 CSV） |
| 上年度承保檔 `LFLxx_yyyy-1.txt` | 同承保資料檔 |
| 上游控制總數 CSV | `來源系統,項目代號,項目名稱,期間,筆數,金額`；項目代號 `NB` 新契約、`CLM` 死亡/失能理賠、`BEN` 生存/祝壽/滿期給付、`INF` 期末有效；期間 `YYYY-MM` 或 `YYYY` |
| 資產負債表 CSV | `科目代號,科目名稱,期初餘額,本期增加,本期減少,期末餘額` |

## 檢核依據

- 明細檢核：`附件二_人壽保險業個人壽險填報手冊_2025填報年度`、`新式個人壽險填報說明手冊範例&檢核規則_2025`。檢核編號沿用手冊「(新)檢核編號」；`X` 開頭為本工具補充的邏輯合理性檢查（預設為警告）。手冊「(放寬不檢)」的條文未實作，文字有歧義的條文以警告呈現。
- 財報勾稽：`src/rulesets/finance.js` 的會計科目表為**示範用簡化版**，實務上請替換為公司正式科目表（含停用日與替代科目）。

## 模擬資料與驗證

`src/mock.js` 依手冊格式產生模擬保單（新契約、持續有效、停效復效、增額、繳清、解約、滿期、疾病/意外死亡、生存還本、外幣保單），並產生一致的上年度申報檔、上游控制總數與資產負債表，再注入 38 項明細錯誤與 14 項對帳/財報差異，解答在 `samples/dirty/answer-key.json`。測試確認：

- 38 項明細錯誤全數偵測，且不誤報在未注入錯誤的保單
- 14 項對帳/財報差異全數找到，且歸因正確（時間差/定義差/待查、根因/連帶、推薦代號）
- 正確資料在多組亂數種子下：明細 0 錯誤、控制總數全部一致、期初 = 上年度期末、財報平衡
- 手冊「範例一(新加保)」的欄位值通過所有檢核；套用自動修正後錯誤數下降

## 專案結構

```
index.html                 網頁介面
src/core.js                固定長度解析、檢核執行、自動修正
src/rulesets/life.js       個人壽險欄位格式、代碼表、檢核規則
src/rulesets/finance.js    會計科目表與財報勾稽規則目錄
src/recon.js               控制總數對帳、期初期末結轉、財報勾稽、退件解碼
src/rules-dsl.js           匯入規則的描述格式、驗證與執行
src/rule-import.js         規則文件讀取、AI 轉換、試跑審核
src/rule-samples.js        規則匯入範例文件與預先轉換結果
src/app-import.js          規則匯入分頁介面
src/report.js              文字 / CSV / HTML 報告、不符資料檔
src/mock.js                模擬資料產生與錯誤/差異注入
src/ai.js                  Claude 分析摘要、問題解釋、退件解讀
tools/validate.js          命令列檢核
tests/                     node:test 測試
samples/                   clean/ 正確範例、dirty/ 含錯誤範例
```

## 延伸

規則集與引擎分離。其他險種（傷害、癌症、年金）的填報手冊格式相近，各加一個 `src/rulesets/*.js` 即可沿用同一套介面、對帳、報告與 AI 分析；主辦單位提供正式檢核規則後，也只需調整規則集。
